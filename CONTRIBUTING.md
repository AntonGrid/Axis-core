# Contributing to Axis Core

Thank you for your interest in Axis Core.

Axis Core is the reference implementation of the Axis Protocol — an open standard. We welcome contributions that improve the protocol, documentation, security, developer experience, and reference implementations.

---

## Principles

Every contribution should follow these principles:

- Keep the protocol open.
- Do not break backward compatibility without discussion.
- Security first.
- Architecture before implementation.
- Documentation is part of the code.

---

## Workflow

1. Fork the repository.
2. Create a feature branch.
3. Make small, isolated changes.
4. Update documentation if needed.
5. Run tests.
6. Submit a Pull Request.

---

## Pull Requests

Good pull requests:

- solve one problem;
- include documentation;
- keep commits clean;
- explain architectural impact.

---

## Coding Standards

- Write readable code.
- Keep functions small.
- Avoid unnecessary dependencies.
- Prefer explicit code over clever code.

---

## Architecture

Before changing the protocol, read:

- [Axis Protocol Specification](https://github.com/AntonGrid/Axis-protocol)
- [Architecture Book](https://github.com/AntonGrid/Axis-protocol/tree/main/docs/philosophy/architecture)
- [Architecture Decision Records (ADR)](https://github.com/AntonGrid/Axis-protocol/tree/main/adr)

Architecture decisions should always be documented.

---

## Security

Never submit:

- private keys;
- passwords;
- API secrets;
- production credentials.

See [SECURITY.md](SECURITY.md) for reporting guidelines.

---

## Questions

Open a GitHub Issue or start a Discussion before making major architectural changes.

---

Thank you for helping build Axis Core.
